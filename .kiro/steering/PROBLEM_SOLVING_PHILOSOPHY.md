# PROBLEM-SOLVING PHILOSOPHY — STEERING RULE

> **Established:** 2026-02-11 by user instruction.
> **Severity:** CRITICAL — Non-negotiable.

---

## The Rule

If you run into a problem, **DO NOT** keep repeating the same approach.

## Required Process

1. **PAUSE** — Stop immediately.
2. **ASSESS** — Define the problem clearly. Separate symptoms from root causes.
3. **RESEARCH** — Check docs, source code, logs, reliable references.
4. **THINK BACKWARD** — Work backward from the desired outcome to find what's missing.
5. **ROOT CAUSE** — Identify the true root cause, not just the surface symptom.
6. **PLAN** — Formulate a clear plan before writing any code.
7. **EXECUTE** — Proceed with a focused, intentional solution.
8. **VERIFY** — Confirm it works. If not, go back to step 1.

## Anti-Patterns (NEVER DO THESE)

- ❌ Trying the same fix multiple times hoping it will work
- ❌ Making random changes without understanding why
- ❌ Ignoring error messages or logs
- ❌ Skipping research because "it should work"
- ❌ Continuing on a path after 2+ consecutive failures without stopping to reassess
